# End-to-End Sales Data Pipeline: Medallion Architecture

## Project Overview
This project implements a professional Medallion Architecture using Databricks, Delta Lake, and Unity Catalog. The system transforms raw sales data from a Volume storage CSV into a high-performance Star Schema for executive reporting. The pipeline manages approximately $3.97M in total revenue across 1,000+ transactions.

## Technical Architecture

### Bronze Layer (Raw Ingestion)
* **Infrastructure:** Orchestrated within `project_catalog` using specific schemas for environment isolation.
* **Ingestion:** Reads raw CSV data from Databricks Volumes with schema inference.
* **Deduplication:** Utilizes PySpark window functions (`row_number()`) to identify and keep only the latest records based on `ingestion_time`.
* **Incremental Logic:** Implements a SQL MERGE to ensure the Bronze table is updated rather than overwritten.

### Silver Layer (Clean & Validated)
* **Quality Gates:** Programmatically filters for valid sales (Price >= 0, Qty > 0, and non-future dates).
* **Quarantine Strategy:** Implements a Quarantine Table (`sales_quarantine`) to capture and audit rejected records without breaking the pipeline.
* **Atomic Upserts:** Uses the MERGE command to update the `sales_clean` table, maintaining data consistency.

### Gold Layer (Star Schema & Analytics)
* **SCD Type 2 (History):** Implemented for `DimProducts` to track category changes over time using `IsCurrent`, `StartDate`, and `EndDate` flags.
* **SCD Type 1 (Attributes):** Managed for dimensions including Region, Customers, SalesRep, Channel, and Payments.
* **Fact Modeling:** A centralized FactSales table optimized via Delta Clustering on `Sale_Date`.
* **Reporting View:** A final `v_Sales_Overview` SQL view that joins 7 tables to provide a flattened, Power BI-ready dataset.

## Automation & Monitoring
* **Scheduled Execution:** The entire pipeline is automated using Databricks Workflows to run every morning at 09:00 AM.
* **Success/Failure Alerts:** Built-in email notifications that alert the team immediately if the data fails to load or if it is a success.
* **System Reliability:** The use of MERGE logic ensures that if a job is interrupted and restarted, it picks up exactly where it left off without duplicating data.

---

## Key Data Engineering Features
* **Identity Columns:** Uses `GENERATED BY DEFAULT AS IDENTITY` for surrogate keys in Dimension tables.
* **Time-Sensitive Joins:** The Fact table load uses complex logic to join with the correct version of an SCD Type 2 product based on the transaction date.
* **Idempotency:** The entire pipeline is designed to be re-run safely without creating duplicate records.
* **Professional Calendar:** Generates a dynamic `DimDate` table covering 2010–2030 with attributes for year, month names, and weekend.
